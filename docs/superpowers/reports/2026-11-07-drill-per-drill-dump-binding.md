# Per-drill dump binding — N2072

Date: 2026-11-07. Parent: `ff2d8ba`. Sequential C01–C12 goal, C02 batch after N2071. This batch makes the drill dump step use each drill's own inventory (one inventory owner per drill): the primary drill dumps from the game-global `drill_items` (kept in sync with its frame), and every other drill dumps from its own frame inventory. Before this slice the dump step always read the game-global, so a second drill's output never reached a belt or the core. It does not make the live loop dump each drill (that stays open), it does not add the two-Drill gate, and it does not accept C02 as a domain or clean-checkout reproducibility.

## What this slice does

- **N2072 `SourceFactoryRuntimeState.source_factory_dump_drill_output_for_cell_state(game, drill_cell, drill_output_item_id) -> Dictionary`** — the per-drill dump step. It reads the drill's own inventory: if the drill cell is the primary (`drill_cell == game.drill_pos`) it reads the game-global `drill_items`; otherwise it reads the drill frame's `items`. It writes back the frame's `items` always, and the game-global only for the primary (so the two stay in sync for the primary and the secondary never touches the primary's inventory). The rest of the step is unchanged (the ring via N2064, the queues via N2067, the dump composition via N2062/N2063, the receiver-only queue write-back). Result keys: `dumped, item_id, receiver_index, receiver_cell, cdump_before, cdump_after, items_after, queues_after, removed, destination, reason` (the same 11 as N2068).
- **The old entry `source_factory_dump_drill_output_state` is now a thin delegate** to the per-drill function, so the N2068 contract and proof keep working unchanged (the N2068 proof still passes, and `simulate_factory` still calls the old entry for the primary).
