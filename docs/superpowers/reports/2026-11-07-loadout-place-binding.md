## Ownership and actual API boundary

`SourceSchematicPlacementState` gains `source_apply_loadout_tile_state` (N2038) and `source_apply_loadout_place_state` (N2039). `PortGame` gains `source_place_loadout_state` (N2040).

- **N2038 per-tile loadout placement.** Resolves the world Tile at (stile + origin); a null Tile is skipped (`tile_missing`) before any removal pass, like Java's early return. With `check` true and a non-core block, the removal pass resolves the air block once and walks `occupied_cells(cell, block)`; every linked tile whose block is not air goes through the N2033 binding with air (the `Tile.remove()` equivalent), re-reading the tile block per cell so a multiblock cleared by its origin is not counted twice. Core stiles skip the pass entirely. The Building is then placed through N2035 with overwrite=true and no valid-place hook (placeLoadout never checks `Build.validPlace`). When the placed Building's block is a CoreBlock and a valid `register_core_hook` is supplied, it is called with (build, team_id) after configureAny. Result keys: `cell, tile, build, placed, skipped, removed, configured, core_placed, core_registered`.
- **N2039 loadout loop.** Finds the first core stile by `implementation == "CoreBlock"`; with none it asserts ("Loadout schematic has no core tile!"), the runtime form of Java's throw. Origin is the placed core position minus the core stile offsets. Stiles run in descending priority order on a copy (the schematic's own tile order is untouched), through N2038. Result keys: `origin, placed, skipped, removed, configured, cores_registered, results` (per-tile results in priority order).
- **N2040 PortGame entry.** `source_place_loadout_state` delegates to N2039 and returns its result. The `source_` prefix is required for implementation discovery (the N2034 lesson).
