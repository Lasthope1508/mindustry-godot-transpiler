Composition, not re-implementation: the shared efficiency machinery (`SourceBuildingEfficiencyState.update_consumption_state` + `apply_update_consumption_state`, via `update_consumption_setup_state`) already folds `{"result": ..., "is_power": true}` rows into the min efficiency — the power consumer's `ConsumePower.efficiency` is `build.power.status` (ConsumePower.java:39). N2152 does not touch it. N2152 supplies the missing pure power row + wires it into the driver.

Pure `SourceTractorBeamTurretBuildState.source_tractor_beam_turret_power_status_row_state(frame: Dictionary, has_power_consumer: bool) -> Dictionary` — `has_power_consumer` false → `{"has_power_row": false, "row": {}}`; true → `{"has_power_row": true, "row": {"result": <live>, "is_power": true}}` where live = 1.0 if `frame.get("power_status", null)` is null else `float(frame.get("power_status"))`. The null→1.0 fold is the assembler convention (UnitAssembler.java:469, before the first graph update).

Driver wiring in `source_tractor_beam_turret_tick_buildings_state(game, seconds)`: iterate placed TractorBeamTurret buildings, bind the frame if missing, refresh frame keys (block_implementation, team_id, rules_state, cheating, enabled), and when `block.properties.has("consumePower")` and enabled and not cheating, the pure row runs through the shared machinery (`update_consumption_setup_state` + `update_consumption_state` + `apply_update_consumption_state`, should_consume=true when enabled, production_valid=true) as the only first-pass row, so `frame["efficiency"]` follows power.status and the tractor-beam eff/edelta fold (TractorBeamTurret.java:84, `float eff = efficiency * coolantMultiplier, edelta = eff * delta();`, TractorBeamTurret.java:117, `rotation = Angles.moveToward(rotation, dest, rotateSpeed * edelta());` — note: the local `edelta` variable, NOT the `edelta()` method call as in PointDefenseTurret.java:81 — with `return efficiency * delta();` in BuildingComp.java:1928) follows it. Live-loop wiring: the driver is called from `simulate_factory` in SourceFactoryRuntimeState.gd after the point-defense tick.

Frame key (decided in RED): the driver uses its OWN family frame key `"source_tractor_beam_turret_building"` (the turret precedent — the generic turret frame `source_turret_building` stays untouched, parallax never binds it). N2142's stamp/write-back only reaches frames whose meta key is in `SourcePlacedPowerGraphState.SOURCE_CONSUMER_FRAME_META_KEYS`, and that list had NO tractor-beam key — so GREEN added `"source_tractor_beam_turret_building"` to that list (one line, SourcePlacedPowerGraphState.gd:140, same mechanism as the point-defense key).

Scope decision (decided in RED): **the TractorBeamTurret implementation only — parallax**. Documented limits in the pure function's comment, same discipline as N2148/N2149/N2150/N2151: (1) power-only first pass — parallax has no other modeled consumers (coolant rows wait for their own slice); the folded efficiency is the min over the *modeled* consumers (power only). (2) No shouldConsume gate — `TractorBeamBuild.shouldConsume()` (TractorBeamTurret.java:141-143, `return super.shouldConsume() && target != null;`) needs live unit-target state the tick does not track yet; the machinery runs with should_consume=true when enabled. (3) No updateTile advance — retarget / coolant consumption / rotation / strength / laser / impulse (TractorBeamTurret.java:78-139) wait for their own slice; the proof carries no progress keys, the eff/edelta fold (TractorBeamTurret.java:84, 117) is what the efficiency keys prove.
