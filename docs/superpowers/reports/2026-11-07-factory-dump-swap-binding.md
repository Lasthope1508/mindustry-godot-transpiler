Date: 2026-11-07. Parent: `31114de`. Sequential C01–C12 goal, C02 batch after N2065–N2067. This batch swaps the live loop: on the drill dump timer `simulate_factory` now dumps through the dump composition over the stored conveyor queues instead of calling the direct dump-to-core fallback (Drill.java:288, BuildingComp.java:68, Conveyor.java:27–28). The wiring is part of this single slice: `simulate_factory` is not a `source_`-prefixed function, so it cannot carry its own contract (the catalog validator only discovers `source_` functions, and every module shard test requires each slice owner to have one). It does not add the belt-advance step (queue items moving along the belt and passing to the next building or the core), it does not sync the queue to the visual item sprites, and it does not accept C02 as a domain or clean-checkout reproducibility.

## Ownership and actual API boundary

- **N2068 `SourceFactoryRuntimeState.source_factory_dump_drill_output_state(game, drill_cell, drill_output_item_id) -> Dictionary`** — the live-loop dump step. It resolves the drill sprite and its frame (the `cdump` cursor lives on the frame, default 0, next to `dominant_item`), the drill size from the catalog block's `properties["size"]` (default 1), the proximity ring via N2064, the queues via N2067, the conveyor rotations from the sprite metas, and the content order from `source_item_catalog["item_names_by_id"]`. It dispatches exactly like `Drill.updateTile`: the specific step (N2062) when the dominant item is held, the any step (N2063) otherwise. It writes back only the receiving belt's queue, the drill inventory (`game.drill_items` and the frame's `items`, kept the same object), and the frame's `cdump`. Capacity 3 and itemSpace 0.4 are the Java constants (Conveyor.java:27–28); `source_block_rotate` is false (Block.rotate defaults false at Block.java:120 and the Drill never sets it) and `next_is_source` is false (the next belt is never the drill itself). Result keys: `dumped, item_id, receiver_index, receiver_cell, cdump_before, cdump_after, items_after, queues_after, removed, destination, reason` (dumped, no_receiver, no_items_block, empty_items, no_proximity, item_not_held, no_sprite, no_frame). `simulate_factory` calls it on the SHOULD_DUMP branch instead of the dump-to-core fallback (the `drill_output_item_id != null` gate is unchanged); the wiring is part of this slice. The legacy `apply_drill_dump` path (only called by `FactoryRuntimeModuleProof` with a fake game) is left untouched.
