## Ownership and actual API boundary

`SourceSchematicPlacementState` (new file) gains `source_apply_schematic_tile_state` (N2035) and `source_apply_schematic_place_state` (N2036). `PortGame` gains `source_place_schematic_state` (N2037). `SourcePlacedBlockPortBridge.record_placed_block` gains a defaulted `team_id: int = 1` parameter, forwarded through the `PortGame` override.

- **N2035 per-tile placement.** Resolves the world Tile at (stile + origin); a null Tile is skipped (`tile_missing`). With `overwrite` false and no valid `valid_place_hook`, placement is fail-closed (`valid_place_unchecked`); a hook that returns false skips the tile (`valid_place_rejected`, `valid_place_checked: true`). `Build.validPlace` has no runtime equivalent yet (rules visibility, core protection, fog, darkness, unit overlap, `canPlaceOn`/`canReplace`), so the hook is caller-supplied and the fail-closed default is the honest one. The Building is created by the placement funnel exactly like player placement (new Sprite2D, `configure_block_sprite`, `World/BlockLayer`, `record_placed_block` with the threaded team), which runs the N2033 setBlock binding. When the Tile keeps a Building and the stile carries a config, `configure_any_state` runs with the caller-supplied `tile_config_callback`. Result keys: `cell, tile, build, placed, skipped, valid_place_checked, configured`.
- **N2036 place loop.** Origin is the center minus half the width/height (GDScript int division matches Java int division for positive sizes); stiles run in source order through N2035. Result keys: `origin, placed, skipped, configured, results` (per-tile result dictionaries in source order).
- **N2037 PortGame entry.** `source_place_schematic_state` delegates to N2036 and returns its result. The `source_` prefix is required: the implementation-discovery rule only sees `source_` / `generated_` / `tile_` functions outside PortBridge files, and the N2034 void-contract failure showed what happens otherwise. The funnel team threading (defaulted sharded, existing callers unchanged) is registered by this batch: the `record_placed_block_input.team_id` symbol belongs to the funnel slice N2034 (owner matches), only the schema key is added here; `test_playable.py`'s signature assertion is updated to the new funnel signature.
