## What this slice does

**N2081 `SourcePlacedPowerGraphState.source_group_buildings_by_origin_state(placed_block_origins) -> Dictionary`** — returns `{origins, count}`: the unique building origins (one per building) from the placed-block origins map. The origins are kept as Variants: the real game stores Vector2i origins, and callers with sprite values (the module proof's fake game, which passes one FakeSprite per building) keep one entry per distinct sprite. `_group_state` now iterates those unique origins instead of every key of the map, so each building is grouped once.

The bug it fixes: `placed_block_origins` holds one key per footprint cell, so `_group_state` grouped a size-2 building 4 times and a size-3 core 9 times — each cell carrying the block's full usage. The lancer (size 2, usage 6.0) was counted 4x, so the graph needed 0.4 instead of Java's 0.1 and coverage was 0.005 instead of 0.02. The counts were also inflated (25 consumers instead of 11).
