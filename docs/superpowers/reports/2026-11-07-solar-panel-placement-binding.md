## A bug this slice exposed and fixed

The placed power graph never actually read the real game. `SourcePlacedPowerGraphState._group_state` iterates `placed_block_origins` and calls `block_from_sprite` on each value — but the real game's `placed_block_origins` maps a cell to its **Vector2i origin**, not to a sprite, so `block_from_sprite` returned null for every block and the graph always reported 0 consumers/producers/batteries. (The N2077 proof passed only because it expected those empty counts.) `SourceTextureRuntimeState.block_from_sprite` now resolves a Vector2i cell to its sprite via `block_sprite_at_cell` before the catalog lookup. The two `test_playable` pins that asserted the old `sprite.get_meta` line were updated to the new `resolved.get_meta` line. After the fix the graph sees the real world: 1 producer (the panel) and 21 consumers counted per origin cell (drill 4 + core 9 + conveyors 7 + duo 1), whose usage is 0 so the graph needs no power. The N2077 proof was updated to the new world (producer_count 1, power_produced 0.12/60, consumer_count 21) — the stale-pin pattern.
