# Battery power-status persistence binding — N2082–N2083

Date: 2026-11-08. Parent: `a1fc6e2`. Sequential C01–C12 goal, C03 batch after N2081. This batch makes a battery's power_status persist across frames, so a charged battery can discharge on a later frame — the C03 gate's battery discharge path, proven live. It does not test the full-power case (coverage 1.0 with produced >= needed), and it does not accept C03 as a domain or clean-checkout reproducibility.

## What these slices do

The bug they fix: `block_battery_state` rebuilds the battery's power_status as 0.0 every frame from the block's static properties, so the charge never persisted and the discharge path could never trigger live (the battery was always empty when a deficit hit).

**N2082 `SourcePlacedPowerGraphState.source_battery_power_status_for_cell_state(game, cell) -> Dictionary`** — reads a battery's stored power_status from its sprite's meta (key `source_battery_power_status`), returning `{status, found, reason}` (status 0.0 when the sprite has none, found false when there is no sprite at the cell). The sprite meta is the per-building persistent state in this port, as the conveyor queue is stored on the conveyor sprite (N2065–N2067).

**N2083 `SourcePlacedPowerGraphState.source_battery_set_power_status_for_cell_state(game, cell, status) -> Dictionary`** — writes the status to the sprite's meta, returning `{stored, reason}`. The live-loop step `source_factory_update_power_graph_state` (N2077) now loads the stored status into each battery dict before the update and writes the result back after; `_group_state` adds the origin cell to each battery dict so the step can resolve the sprite. (The wiring is folded into N2083, the slice of the write function it calls — the N2068 lesson.)

## Godot proof

`BatteryPowerStatusProof` — **5/5 checks true, `matches=true`**, on the real Main scene. Checks: the battery at (23, 7) starts with no stored status (found, status 0.0); the write stores 0.5 and the read returns it; with the battery pre-charged to 0.5 (stored energy 2000), the deficit step (needed 0.1, produced 0.002) discharges it — `power_battery_used` is the full deficit 0.098 and the stored status drops below 0.5; a second step reads the persisted status (not rebuilt as 0.0) and discharges it further. Godot `4.6.2.stable.official.71f334935`, 0 errors.

The N2077/N2078/N2079/N2080/N2081 proofs are unaffected: they run the step on an empty battery (no stored status), so their counts and coverage stand. The test_playable pin for the battery append line in `_group_state` was updated to the new lines (the stale-pin pattern).
