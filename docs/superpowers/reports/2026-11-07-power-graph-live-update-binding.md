# Live-loop power graph update binding — N2077

Date: 2026-11-07. Parent: `d8172e3`. Sequential C01–C12 goal, C03 batch after N2076. This batch wires the power graph update into the live loop: each frame `simulate_factory` runs the placed power graph's update (PowerGraph.java), so the graph's balance and consumer statuses are actually recomputed instead of the bound update sitting unused. It does not add a power producer or consumer to the bootstrap world (the graph is empty there, so the update is a no-op in the current world), and it does not accept C03 as a domain or clean-checkout reproducibility.

## What this slice does

**N2077 `SourceFactoryRuntimeState.source_factory_update_power_graph_state(game, delta) -> Dictionary`** — the live-loop step. It reads the placed power graph's consumers/producers/batteries from the game (via `SourcePlacedPowerGraphState._group_state` with the game's default callbacks), then runs the bound update (`SourcePowerGraphState.update_state`, the N1617 function) with energy_delta 0.0 and the frame delta. Result keys: `power_needed, power_produced, consumer_count, producer_count, battery_count, update` (the full update result: cheat_state, balance_state, battery_distribute_state). `simulate_factory` calls it after the conveyor advance step (folded into the slice, per the N2068 lesson — a wiring change inside a non-`source_` function cannot carry its own contract).
