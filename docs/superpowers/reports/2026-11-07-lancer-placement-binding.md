## A divergence this slice exposes (not fixed here)

The placed power graph counts each consumer **per footprint cell**, and each cell carries the block's full usage. The size-2 lancer is therefore counted 4 times with usage 6.0 each, so the graph needs 4 x 6.0/60 = 0.4 per frame. Java's PowerGraph counts each building once, so the Java need would be 0.1 and coverage 0.02, not 0.005. This is the existing `_group_state` per-cell counting (the N2078 note: not to be changed casually — it also affects the drill's 4 cells and the core's 9, though their usage is 0 so only the count, not the need, was visible before). Fixing it means grouping by origin building in `_group_state`, which changes every consumer/producer/battery count the proofs pin — a separate slice, deferred.

The lancer registers as a turret cell (`Block.is_turret` includes PowerTurret), so `simulate_turrets` iterates it — but it uses the duo's stats (`selected_playable_turret`) and finds no enemy target in the bootstrap world, so it idles. Per-turret stats in the sim are a separate concern.
