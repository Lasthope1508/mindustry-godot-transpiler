## Ownership and actual API boundary

`SourceBlockGeometry` gains `source_assign_build_team_state(sprite, team_id) -> Dictionary` plus `SOURCE_TEAM_SHARDED_ID := 1`, `SOURCE_TEAM_DERELICT_ID := 0`, `SOURCE_BUILD_TEAM_META_KEY := "team_id"` (N2032). `SourceWorldTerrainRuntimeState` gains `source_apply_placed_tile_set_block_state(game, block, cell, sprite, team_id, rotation) -> Dictionary` (N2033). `SourcePlacedBlockPortBridge.record_placed_block` routes through the binding (N2034).

- **N2032 team identity.** Assigns `Team.sharded` (id 1) to the placed sprite meta; `Team.derelict` (id 0) is the no-Building default. The consts are the `build_team` hook target for the binding; `Team.sharded.id` is an exact substring of `Block.java:979` (precedent symbol `block_icons.team_sharded_id`, N1733), while `Team.derelict.id` appears nowhere upstream, so the derelict const is registered via the `Team.java` field-declaration expr instead.
- **N2033 binding.** Builds all 38 setBlock hooks from the game context: world lookup via `source_world_tile`; previous build from `placed_blocks` (with a freed-instance guard); entity provider = the placed sprite; entity init = existing `game_initialize_sprite`; `remove_build` erases the old sprite from `placed_blocks` and every `placed_block_origins` entry whose value equals the old sprite's `origin_cell` meta, then `queue_free()`s it; proximity = the existing Drill recompute, team-filtered like `Building.updateProximity` — self recompute first, then `onProximityUpdate` on each unique same-team edge neighbour via `edge_points_state(build_size)`; `build_team` = N2032; `neighbour_changing` via the neighbour Tile's `changing` flag; `set_block_air` = the recursive binding call with air + null sprite. Deferred no-ops, per the N2021 precedent (no runtime bus/cache yet): `fire_pre_changed`, `fire_changed`, `recache`, `recache_wall`, `on_removed`, `block_changed`. Result keys: `tile, build, removed_old_build, proximity_updated, changed_event_fired, recache_called`. The catalog `properties` have no `hasBuilding`/`update`/`destructible` keys, so the binding uses `sprite != null` for `has_building` and `properties.get("update", false)` for `update` (the Java field default; inert because sprite init is unconditional). `is_static` compares `cacheLayer` against `"walls"`; no placed block is static in practice (all placed blocks have `cacheLayer` `"normal"` upstream too), so the recache guard never fires.
- **N2034 wiring.** The binding runs **before** `record_cells` overwrites the placement index, so the previous Building is still resolvable for removal and the new sprite is inited, assigned and proximity-updated through the Tile mutation itself. The old separate proximity call is removed; the old field/proxy-assignment path is kept as a fallback when `source_world_tiles` is empty (headless/degenerate games without a world store). `record_placed_block` uses the parent class's existing `source_block_geometry` const — redeclaring it was a parse error, already fixed. **Out-of-world fallback (found by the full suite):** the liquid-hydration proof places electrolyzers at `(200,200)` / `(210,200)`, outside the 48x32 world, and the binding asserted on the unresolvable Tile. The wiring now calls the binding only when `source_world_tile` resolves the cell; otherwise it falls back to the legacy init after `record_cells`, exactly like the pre-binding path. The binding keeps its assert for the in-world contract.

N2034 has no contract by design: the wiring lives in PortBridge `record_placed_block`, whose name the implementation-discovery rule cannot see (PortBridge files only discover `source_` / `generated_` functions), so the first version of this batch registered a void contract that failed catalog validation with two errors (`void return requires an explicit -> void implementation`, `facade/module function not discovered`). The contract was removed; the slice is covered by ledger + symbols + schema + the runtime proof, and symbol owners without a contract are established practice (99 owners). Renaming the funnel to `source_record_placed_block` was rejected: the name is shared by `PortGame.gd`, `SourceBlockPlacement.gd` and three other slices' tests, and renaming an existing runtime name to satisfy the validator would invent a name the upstream has no equivalent for.
