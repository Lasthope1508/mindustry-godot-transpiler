N2163 is the PayloadUnloader family's live read — the same proven N2145–N2162 pure-row pattern, one new file over. Third payload-producer family: the deferred list in the N2162 handoff named payload producers (PayloadUnloader / PayloadMassDriver / UnitCargoLoader / PayloadDeconstructor) as the next family group after PayloadLoader; PayloadUnloader is first in that order.

PayloadUnloader extends PayloadLoader, NOT a drill or factory, so it cannot reuse an existing frame key; it gets its own family frame key (the mechanical-pump / beam-drill / mend-projector / overdrive-projector / force-projector / base-shield / regen-projector / constructor / payload-loader precedent).

Composition, not re-implementation: the shared efficiency machinery (`SourceBuildingEfficiencyState.update_consumption_state` + `apply_update_consumption_state`, via `update_consumption_setup_state`) already folds `{"result": ..., "is_power": true}` rows into the min efficiency — the power consumer's `ConsumePower.efficiency` is `build.power.status` (ConsumePower.java:39). N2163 does not touch it. N2163 supplies the missing pure power row + wires it into the driver. The port has NO SourcePayloadUnloader* files at all yet — no display/runtime state to lean on. The efficiency fold this slice proves is the unload gate (PayloadUnloader.java:69, `if(efficiency > 0.01f && timer(timerLoad, loadTime / efficiency)){`), with the battery unload (PayloadUnloader.java:98, `float total = payload.build.power.status * cap;`).

Pure `SourcePayloadUnloaderBuildState.source_payload_unloader_power_status_row_state(frame: Dictionary, has_power_consumer: bool) -> Dictionary` — `has_power_consumer` false → `{"has_power_row": false, "row": {}}`; true → `{"has_power_row": true, "row": {"result": <live>, "is_power": true}}` where live = 1.0 if `frame.get("power_status", null)` is null else `float(frame.get("power_status"))`. The null→1.0 fold is the assembler convention (UnitAssembler.java:469, before the first graph update).

Driver wiring in `source_payload_unloader_tick_buildings_state(game, seconds)`: iterate placed PayloadUnloader buildings, bind the frame if missing, refresh frame keys (block_implementation, team_id, rules_state, cheating, enabled), and when `block.properties.has("consumePower")` and enabled and not cheating, the pure row runs through the shared machinery (`update_consumption_setup_state` + `update_consumption_state` + `apply_update_consumption_state`, should_consume=true when enabled, production_valid=true) as the only first-pass row, so `frame["efficiency"]` follows power.status and the unload gate (PayloadUnloader.java:69) follows it. Live-loop wiring: the driver is called from `simulate_factory` in SourceFactoryRuntimeState.gd next to the payload-loader tick.

Frame key (decided in RED): the driver uses its OWN family frame key `"source_payload_unloader_building"` (verified no collision: grep finds no `source_payload_unloader_building` anywhere in the port). N2142's stamp/write-back only reaches frames whose meta key is in `SourcePlacedPowerGraphState.SOURCE_CONSUMER_FRAME_META_KEYS`, and that list had NO payload-unloader key — so GREEN added `"source_payload_unloader_building"` to that list (one line, same mechanism as the payload-loader key).

Scope decision (decided in RED): **the PayloadUnloader implementation only — payload-unloader**. Families considered and rejected, with reasons (catalog `content_registry.json`, verified against Java + drivers):
- Remaining payload producers (PayloadMassDriver / UnitCargoLoader / PayloadDeconstructor): separate family slices, deferred — the next families after PayloadUnloader.
- PayloadUnloader wins: first in the deferred order after PayloadLoader, 1 block, direct unload-gate efficiency dependency — the smallest, safest next family.

Documented limits in the pure function's comment, same discipline as N2148–N2162: (1) power-only first pass — PayloadUnloader inherits a DYNAMIC power consumer (consumePowerDynamic, PayloadLoader.java:80 — maxPowerConsumption 40f + basePowerUse when hasBattery() && !exporting, else basePowerUse) besides the static consumePower(2f) def, so the folded efficiency is the min over the *modeled* consumers (power only) with the dynamic usage value deferred. (2) shouldConsume gate deferred — PayloadUnloaderBuild inherits shouldConsume() returning payload != null (PayloadLoader.java:240-242); payload state is not tracked yet, so the machinery runs with should_consume=true when enabled (the MendProjector suppression precedent). (3) shouldExport gate deferred — shouldExport() (PayloadUnloader.java:116-122) needs payload items/liquids/battery state. (4) No updateTile advance — moveInPayload / moveOutPayload / unload items+liquids / battery unload / lastOutputPower / dumpAccumulate (PayloadUnloader.java:50-110) wait for their own slices; the proof carries no unload/export/battery/power-output keys, the unload gate (PayloadUnloader.java:69) is what the efficiency keys prove. (5) No accept/handle payload rows — acceptPayload fits maxBlockSize (PayloadLoader.java:102-115, inherited) is payload acceptance, not tick state; PayloadUnloaderBuild overrides acceptItem/acceptLiquid to return false (PayloadUnloader.java:35-44).
