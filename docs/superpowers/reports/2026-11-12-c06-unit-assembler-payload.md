## What changed

N2124 wired the assembler's per-class `shouldConsume()` body but left its payload conjunct on a permissive frame default: `consPayload` efficiency (`ConsumePayloadDynamic.java:24-32`) needs the building's payload module (the payload stacks held), which the port did not model. Java holds them in `UnitAssemblerBuild.blocks` (UnitAssembler.java:323, `public PayloadSeq blocks = new PayloadSeq();`), returned by `getPayloads()` (UnitAssembler.java:717-719, `return blocks;`): an `ObjectIntMap<UnlockableContent>` of held payload counts plus its total. The efficiency reads `float mult = multiplier.get(build); for(PayloadStack stack : payloads.get(build)){ if(!build.getPayloads().contains(stack.item, Math.round(stack.amount * mult))){ return 0f; } } return 1f;` — binary 1/0, with `PayloadSeq.contains(block, amount)` = `get(block) >= amount` (PayloadSeq.java:71-73). The multiplier is the family's `Rules.unitCost` callback (UnitAssembler.java:175, `consumeBuilder.each(c -> c.multiplier = b -> state.rules.unitCost(b.team))`), the N2097 callback, not the `Consume` default (Consume.java:18, `b -> 1f`).

N2129 adds `SourceUnitFactoryBuildState.source_unit_factory_assembler_payload_state(frame, plan)` — the frame's `blocks` dict (content name to held count; a missing key reads as an empty module, since Java constructs the field empty, never null) plus the efficiency read over the current tier's `AssemblerUnitPlan` requirements (vanquish: stell 4 + tungsten-wall-large 10; conquer: locus 6 + carbide-wall-large 20). It returns the efficiency, a snapshot of the module, and its total (`PayloadSeq.total()`). The function is pure and is NOT wired into the `shouldConsume` gate yet — the gate keeps reading the frame's `payload_efficiency` default (1.0, N2124) until the wiring slice lands it with the blocks the payload intake fills, like the N2128 trigger before the production wiring.
