## What these slices do

Both live in a new file, `SourceTeamsRuntimeState.gd`, operating on a `teams_state` dict (`{"teams": {team_id: {"cores": [...], "buildings": [...], "units": [...], "core_enemies": [...]}}, "active": [team_ids], "rules": {"wave_team": int, "waves": bool}}`). Team ids follow the runtime convention (derelict 0, sharded 1, crux 2). The `active()` check and `updateEnemies()` recompute are internal helpers in the same file.

- **N2074 `SourceTeamsRuntimeState.source_teams_register_core_state(teams_state, team_id, core_ref) -> Dictionary`** — adds the core ref to the team's cores if not present (`registered` false on a duplicate), and if the team is now active and wasn't in the active list, adds it and recomputes enemies (`active_changed` true). Result keys: `registered, active_changed, active, enemies_by_team, teams_state`.
- **N2075 `SourceTeamsRuntimeState.source_teams_unregister_core_state(teams_state, team_id, core_ref) -> Dictionary`** — removes the core ref from the team's cores if present (`unregistered` false when missing), and if the team is no longer active and was in the active list, removes it and recomputes enemies (`active_changed` true). Result keys: `unregistered, active_changed, active, enemies_by_team, teams_state`.
