## What changed

N2130 empties the assembler's payload module at unit completion, but nothing ever filled it: Java fills it when a payload arrives, through `yeetPayload` (UnitAssembler.java:688-690, `blocks.add(payload.content(), 1);`), called from `updateTile` at UnitAssembler.java:500-503 once `moveInPayload()` has the payload in position (`if(moveInPayload() && !wasOccupied){ yeetPayload(payload); payload = null; }`). The add is gated by `acceptUnitPayload` (UnitAssembler.java:710-714) for unit payloads and `acceptPayload` (UnitAssembler.java:722-727) for block payloads, both over `plan().requirements` with the cap `blocks.get(content) < Mathf.round(b.amount * state.rules.unitCost(team))`; the block gate additionally requires `(this.payload == null || (source instanceof UnitAssemblerModuleBuild))` and subtracts 1 when the module source's in-transit payload already counts as one (`contentEquals` case). `PayloadSeq.add` (PayloadSeq.java:33-38) is `payloads.increment(block, amount); total += amount;` with a null early-return (`add(block)` is `add(block, 1)`; `get(block)` reads 0 when missing).

N2131 adds `SourceUnitFactoryBuildState.source_unit_factory_assembler_payload_intake_state(frame, plan, payload)` next to the N2130 trigger function. The `payload` descriptor carries `content`, `kind` (`"block"` → the acceptPayload gate, `"unit"` → acceptUnitPayload) and `source_is_module` (`source instanceof UnitAssemblerModuleBuild`). The multiplier is the family's `Rules.unitCost` callback (UnitAssembler.java:175, the N2097 callback), read through `source_consume_state.source_cost_multiplier_for_block_state(frame)` like N2129/N2130. If accepted: `blocks[content] = blocks.get(content, 0) + 1`, total += 1, `added = 1`. If rejected: nothing changes, `added = 0`. A null/empty content can never pass a gate — no requirement row matches it — so the `PayloadSeq.add` null early-return needs no separate branch. It returns `{"source_owner": ..., "accepted": bool, "added": 0|1, "blocks": <dup>, "total": int}`. The function is pure apart from the frame's own module and is NOT wired into the tick driver or the shouldConsume gate — the intake runs only when a payload arrives; the live-loop call site (`moveInPayload() && !wasOccupied`, UnitAssembler.java:500-503) is a later wiring slice.
