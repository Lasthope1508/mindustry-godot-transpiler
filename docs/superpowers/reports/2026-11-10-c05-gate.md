# C05 gate: reinitialize_consumers for Factory + AdjacentFactory families — N2116

Date: 2026-11-10. Batch: N2116 (single slice, SSOT slice). SSOT +16/+1/+2/+4 → 11018 / 1567 / 1471 / 2733; audit `totalSourceFunctions` stays 1335.

## What changed

N2112/N2115 bound each factory frame's consumers once, but a block replacement never refreshed them. In Java, `Tile.changeBuild` (Tile.java:636-657) removes the old Building and inits a brand-new one (`Block.newBuilding()`, Block.java:1002), whose `reinitializeConsumers()` (Block.java:1481-1497) re-reads the consumeBuilder and rebuilds the optional / non-optional / update consumer arrays. The port reuses the sprite node when the same sprite is re-recorded with a different block (`initialize_sprite` overwrites the block-id meta but keeps the family frame), so the tick kept running the old block's actors against the new block's rows — and indexed past the end of the actor list when the new block had more rows. N2116 closes that hole, and with it C05.

- `SourceFactoryBuildState.source_factory_reinitialize_consumers_state(frame, block, catalog, amounts)` and `SourceAdjacentFactoryBuildState.source_adjacent_factory_reinitialize_consumers_state(frame, block, catalog, amounts)` — a frame already stamped for this block takes the normal once-only bind path (`reinitialized=false`); a frame stamped for another block drops its old RuntimeConsumer actors (N2100's invalidate, the cache-invalidation half of reinitializeConsumers), clears its item and liquid stores for the fresh Building's own empty ItemModule/LiquidModule (BuildingComp.java:145-146, init creates a fresh ItemModule/LiquidModule per Building), and rebinds from the new block's consumeBuilder, stamping the new block id. A null block reinitializes nothing. New owner constants `PORT_GAME_SOURCE_FACTORY_BUILD_REINITIALIZE_CONSUMERS_STATE` and `PORT_GAME_SOURCE_ADJACENT_FACTORY_BUILD_REINITIALIZE_CONSUMERS_STATE` in `SourceRuntimeOwnerGameplayRegistry.gd`.
- The tick drivers `source_factory_tick_buildings_state` and `source_adjacent_factory_tick_buildings_state` now reinitialize through these instead of binding directly; the two older consumer-binding test modules pin the new driver call.
- The ledger row cites the gate's exact Java evidence: `Tile.changeBuild`, `Block.reinitializeConsumers`, `BuildingComp.updateConsumption`, `ConsumeItems.efficiency`, `ConsumeLiquid.update`.
