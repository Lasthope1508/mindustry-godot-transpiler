## Ownership and actual API boundary

- **N2062 `SourceBuildingItemDumpState.source_drill_dump_step_state(items, proximity_cells, todump, cdump, has_items, queues_by_cell, capacity, item_space, conveyor_rotation_by_cell, source_block_rotate, next_is_source, drill_cell, drill_size) -> Dictionary`** — the specific dump step: the N2047 dump-specific composition with hooks built from the N2060/N2061 conveyor functions. The accept hook computes the facing edge per neighbor via N2059 (`source_block_facing_edge_state(drill_size, drill_cell.x, drill_cell.y, other.x, other.y)`) and passes that edge cell as the source cell — passing the drill origin (7,8) directly would fail for the size-2 drill, since the conveyor at (9,8) is not near the origin. The handle hook derives the conveyor's items-module count by counting the item in the queue's ids (Java keeps the conveyor's items module and queue in sync) and writes the updated queue back into the `queues_after` dict. Cells without a queue fail closed in the accept hook. Result keys: `dumped, item_id, receiver_index, receiver_cell, cdump_before, cdump_after, items_after, queues_after, removed, destination, reason` (dumped, no_receiver, no_items_block, empty_items, no_proximity, item_not_held). A full belt refuses with `no_receiver` and the item stays — Java has no core fallback in `dump()`.
- **N2063 `SourceBuildingItemDumpState.source_drill_dump_any_step_state(items, proximity_cells, cdump, has_items, content_item_ids, queues_by_cell, capacity, item_space, conveyor_rotation_by_cell, source_block_rotate, next_is_source, drill_cell, drill_size) -> Dictionary`** — the any dump step: the N2048 dump-any composition (`dump(null)`) with the same hooks; items are tried in content order per neighbor, so a neighbor rejecting copper still takes lead. Result keys: the same 11 as N2062.
- **N2064 `SourceBlockGeometry.source_block_proximity_cells_state(block_size, tile_x, tile_y) -> Dictionary`** — the proximity ring from `Edges.getEdges`: the ring offsets for a block size, built bottom/top/left/right then sorted by atan2 angle ascending (-180..180), translated to absolute cells. Result keys: `cells, count, reason` (ring, invalid_size). Size 2 at (7,8) gives [(7,7), (8,7), (9,8), (9,9), (8,10), (7,10), (6,9), (6,8)] — the conveyor at (9,8) is index 2. Size 1 gives the four direct neighbors in angle order [(0,-1), (1,0), (0,1), (-1,0)] offsets. Java's `Arrays.sort` is stable, but no two ring points share a ray from the center, so the (angle, x, y) tiebreak never fires for sizes 1–4.
