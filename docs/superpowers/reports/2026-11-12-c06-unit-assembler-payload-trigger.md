## What changed

N2129 modeled the assembler's payload module (`UnitAssemblerBuild.blocks`, a `PayloadSeq`) and the `ConsumePayloadDynamic` efficiency read over it, but the stacks never left: Java removes them only at unit completion, through `BuildingComp.consume()` (BuildingComp.java:1911-1915), which triggers every consumer, and the payload row removes `Math.round(amount * multiplier)` per requirement stack through `ConsumePayloadDynamic.trigger` (ConsumePayloadDynamic.java:34-39): `float mult = multiplier.get(build); for(PayloadStack stack : payloads.get(build)){ build.getPayloads().remove(stack.item, Math.round(stack.amount * mult)); }` — the rows are `plan().requirements` (UnitAssembler.java:158, `consume(consPayload = new ConsumePayloadDynamic((UnitAssemblerBuild build) -> build.plan().requirements));`). `PayloadSeq.remove(block, amount)` (PayloadSeq.java:40-42) is `add(block, -amount)` — no clamp: a short stack goes negative before the clear (unlike `ItemModule.remove` in N2128, which clamps), so the port records the requested removal per stack. `UnitAssemblerBuild.spawned()` (UnitAssembler.java:543-571) calls `consume()` first (line 546), then creates the unit, then `progress = 0f; ... blocks.clear();` (line 571) at the end; `PayloadSeq.clear()` (PayloadSeq.java:61-64) is `payloads.clear(); total = 0;`. The multiplier is the family's `Rules.unitCost` callback (UnitAssembler.java:175, `consumeBuilder.each(c -> c.multiplier = b -> state.rules.unitCost(b.team))`, the N2097 callback); the `Consume` default is `b -> 1f` (Consume.java:18).

N2130 adds `SourceUnitFactoryBuildState.source_unit_factory_assembler_payload_trigger_state(frame, plan)` — the payload twin of the N2128 `consume()` trigger. It removes `int(round(float(stack.get("amount", 0)) * multiplier))` per requirement stack from the frame's `blocks` dict (no clamp — mirror `PayloadSeq.remove`), records the requested removal per item in `removed` (duplicate rows accumulate), then clears the module unconditionally (`spawned()` always clears, including extra blocks beyond the plan and short/empty modules). Zero-amount rows are skipped (they remove nothing, like the N2129 efficiency where they cannot change the result). It returns `{"source_owner": ..., "triggered": <stacks>, "removed": {item: amount}, "cleared": true, "blocks": {}, "total": 0}`. The function is pure apart from the frame's own module and is NOT wired into the tick driver or the `shouldConsume` gate — the tick never calls it; the live production wiring (progress advance + the call at completion) is a later slice.
