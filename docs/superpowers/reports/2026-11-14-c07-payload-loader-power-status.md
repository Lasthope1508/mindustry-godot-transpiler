Second payload-producer family: the deferred list in the N2161 handoff named payload producers (PayloadLoader / PayloadUnloader / PayloadMassDriver / UnitCargoLoader / PayloadDeconstructor) as the next family group after Constructor; PayloadLoader is first in that order.

PayloadLoader extends PayloadBlock, NOT a drill or factory, so it cannot reuse an existing frame key; it gets its own family frame key (the mechanical-pump / beam-drill / mend-projector / overdrive-projector / force-projector / base-shield / regen-projector / constructor precedent).

Composition, not re-implementation: the shared efficiency machinery (`SourceBuildingEfficiencyState.update_consumption_state` + `apply_update_consumption_state`, via `update_consumption_setup_state`) already folds `{"result": ..., "is_power": true}` rows into the min efficiency — the power consumer's `ConsumePower.efficiency` is `build.power.status` (ConsumePower.java:39). N2162 does not touch it. N2162 supplies the missing pure power row + wires it into the driver. The port has NO SourcePayloadLoader* files at all yet — no display/runtime state to lean on. The efficiency fold this slice proves is the load gate (PayloadLoader.java:157, `if(efficiency > 0.01f && timer(timerLoad, loadTime / efficiency)){`), with the battery charge (PayloadLoader.java:202, `float powerInput = power.status * (basePowerUse + maxPowerConsumption);`).

Pure `SourcePayloadLoaderBuildState.source_payload_loader_power_status_row_state(frame: Dictionary, has_power_consumer: bool) -> Dictionary` — `has_power_consumer` false → `{"has_power_row": false, "row": {}}`; true → `{"has_power_row": true, "row": {"result": <live>, "is_power": true}}` where live = 1.0 if `frame.get("power_status", null)` is null else `float(frame.get("power_status"))`. The null→1.0 fold is the assembler convention (UnitAssembler.java:469, before the first graph update).

Driver wiring in `source_payload_loader_tick_buildings_state(game, seconds)`: iterate placed PayloadLoader buildings, bind the frame if missing, refresh frame keys (block_implementation, team_id, rules_state, cheating, enabled), and when `block.properties.has("consumePower")` and enabled and not cheating, the pure row runs through the shared machinery (`update_consumption_setup_state` + `update_consumption_state` + `apply_update_consumption_state`, should_consume=true when enabled, production_valid=true) as the only first-pass row, so `frame["efficiency"]` follows power.status and the load gate (PayloadLoader.java:157) follows it. Live-loop wiring: the driver is called from `simulate_factory` in SourceFactoryRuntimeState.gd next to the constructor tick.

Frame key (decided in RED): the driver uses its OWN family frame key `"source_payload_loader_building"` (verified no collision: grep finds no `source_payload_loader_building` anywhere in the port). N2142's stamp/write-back only reaches frames whose meta key is in `SourcePlacedPowerGraphState.SOURCE_CONSUMER_FRAME_META_KEYS`, and that list had NO payload-loader key — so GREEN added `"source_payload_loader_building"` to that list (one line, same mechanism as the constructor key).

Scope decision (decided in RED): **the PayloadLoader implementation only — payload-loader**. Families considered and rejected, with reasons (catalog `content_registry.json`, verified against Java + drivers):
- Remaining payload producers (PayloadUnloader / PayloadMassDriver / UnitCargoLoader / PayloadDeconstructor): separate family slices, deferred — the next families after PayloadLoader.

Documented limits in the pure function's comment, same discipline as N2148–N2161: (1) power-only first pass — PayloadLoader has a DYNAMIC power consumer (consumePowerDynamic, PayloadLoader.java:80 — maxPowerConsumption 40f + basePowerUse when hasBattery() && !exporting, else basePowerUse) besides the static consumePower(2f) def, so the folded efficiency is the min over the *modeled* consumers (power only) with the dynamic usage value deferred. (2) shouldConsume gate deferred — PayloadLoaderBuild overrides shouldConsume() to return payload != null (PayloadLoader.java:240-242); payload state is not tracked yet, so the machinery runs with should_consume=true when enabled (the MendProjector suppression precedent). (3) No updateTile advance — moveInPayload / moveOutPayload / load items+liquids / battery charge (PayloadLoader.java:143-220) wait for their own slices; the proof carries no load/export/battery keys, the load gate (PayloadLoader.java:157) is what the efficiency keys prove. (4) No accept/handle payload rows — acceptPayload fits maxBlockSize (PayloadLoader.java:102-115) is payload acceptance, not tick state.
