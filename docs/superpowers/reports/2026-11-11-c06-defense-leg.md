This is the C06 defense leg: the duo leads its shots at the intercept point (`Predict.intercept`) and a bullet-killed enemy is swept from the live loop (the death sweep).

## What changed

- New `SourcePredictState.source_predict_intercept_state(src_x, src_y, dst_x, dst_y, dst_vx, dst_vy, bullet_speed, time_delta)` implements `Predict.intercept` (Predict.java: the per-frame displacement divided by `Time.delta`, the quadratic `a = dstv^2 - v^2`, `b = 2(dstv . t)`, `c = t^2` solved for the smallest positive root, else the current position) with `source_predict_quad_state(a, b, c)` for `Predict.quad` (the `|a| < 1e-6` linear branch, the non-negative discriminant branch). The intercept is pure and checked against hand-computed values before any game exists.
- New `SourceTurretCombatState.source_turret_target_position_state(game, origin, target)` implements `Turret.targetPosition` (Turret.java:453-470: `predictTarget` — the Turret default, true — and `bullet.speed >= 0.01f` run the intercept, else the current position; a zero intercept falls back to the current position; the duo runs `accurateDelay` with `moveWhileCharging`, so the charge offset is zero; the target's per-frame displacement is its world speed toward the core for one live-loop tick). It is wired into `game_angle_to_target` before the pinned return line, reassigning `target` (to the intercept-point dict) and `origin` (cell → world); the pinned line stays textually identical, and the wiring only runs for a Vector2 cell origin with a real enemy dict (has "type") — the tractor beam (dict origin) and the module proof (fake target, no "type") keep the plain angle.
- New `SourceEnemyUnitRuntimeState.source_enemy_units_sweep_dead_state(game)` is the kill half of the death chain (`HealthComp.damage` kills at `health <= 0`, HealthComp.java:76-77; `HealthComp.kill` clamps the health, marks it dead and removes it, :33-41; a non-flying unit's `killed()` destroys it, UnitComp.java:959-968; `remove()` drops it from its team, :603-608), called at the top of `simulate_units` so a bullet-killed enemy never moves again. It returns `{swept_count, swept_health, remaining_count}` and is a no-op for a null game.
- New owner constants `PORT_GAME_SOURCE_PREDICT_INTERCEPT_STATE`, `PORT_GAME_SOURCE_PREDICT_QUAD_STATE`, `PORT_GAME_SOURCE_TURRET_TARGET_POSITION_STATE`, `PORT_GAME_SOURCE_ENEMY_UNITS_SWEEP_DEAD_STATE` in `SourceRuntimeOwnerGameplayRegistry.gd`.

## The two live-loop gaps this proof exposed

Proving the leg exposed two gaps in the defense chain, both fixed in this slice.

- **The sim aimed from the turret's grid cell.** `turret_fire_state` and `turret_shot_application_state` both used `Vector2(cell)` as the origin, so `find_enemy_target` measured the 160px range from (19, 7) in pixel space and the bullet spawned there. The turret only acquired the dagger while it was in the far west, and every shot missed by the lead distance. Java aims from the building's world x/y, so the origin is now the turret's world position at all three call sites: `find_enemy_target` converts the cell before the range check (via `call("grid_to_world", ...)` — a direct call is not in that bridge's extends chain and breaks PortGame loading), the aim path converts it before the angle, and the shot application converts it before the bullet origin (via the `game` in the shot context, falling back to the cell when the game is absent, as in the module proof).
- **There was no lead at all.** The aim used the target's current sprite position while the bullet needs ~64 ticks to cross 160px (2.5 px/tick) and the dagger walks ~32px in that time (0.5 px/tick). The duo's shots were always behind a moving target. The intercept now feeds the aim, so the bullet meets the dagger ahead of where it is.
