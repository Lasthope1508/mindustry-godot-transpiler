## What changed

After N2118 (warmup, liquid output, totalProgress), the last statement of `GenericCrafterBuild.updateTile()` still unwired was `dumpOutputs()` (GenericCrafter.java:317+). N2119 wires it through the live loop, in Java order (after the craft check).

- `SourceFactoryBuildState.source_factory_dump_interval_state(dump_time, time_scale)` implements the dump interval `dumpTime / timeScale` (GenericCrafter.java:319): dumpTime is Block.dumpTime, 5 (Block.java:438; no factory initializer overrides it); timeScale is the building time scale, 1f by default (BuildingComp.java:98). A zero time scale makes the interval infinite, and `TimerComp.timer` returns false for an infinite time (TimerComp.java:11).
- `SourceFactoryBuildState.source_factory_dump_timer_state(dump_timer, seconds, dump_time, time_scale)` implements `TimerComp.timer(timerDump, dumpTime / timeScale)` (GenericCrafter.java:319; TimerComp.java:10-13): returns false for an infinite interval, otherwise fires when the accumulated timer reaches the interval and resets it to 0.0. Time advances in seconds, so the port accumulates the Godot delta in seconds.
- `SourceFactoryBuildState.source_factory_dump_liquid_state(game, cell, block, liquids, liquid_ids, liquid_name, output_dir)` implements `BuildingComp.dumpLiquid(liquid, 2f, dir)` (BuildingComp.java:886-908): returns when the building holds <= 0.0001; a null game or block, or an unknown liquid, dumps nothing. The transfer flow is `(held/cap - dest/destCap) * cap / 2`, capped by the destination's free space, and the frame's `cdump` cursor is updated to the neighbor actually dumped to.
- `SourceFactoryBuildState.source_factory_dump_outputs_state(game, frame, cell, block, liquids, liquid_ids, seconds, time_scale)` implements `GenericCrafterBuild.dumpOutputs()` (GenericCrafter.java:317-332): the item rows dump only when `outputItems != null && timer(timerDump, dumpTime / timeScale)` fires (one item per fired timer, via `BuildingComp.dump(Item)` to the first accepting belt neighbor); every output liquid dumps every tick via `dumpLiquid(outputLiquids[i].liquid, 2f, dir)` with `dir = liquidOutputDirections.length > i ? liquidOutputDirections[i] : -1` (GenericCrafter.java:327-328). A null block dumps nothing; a liquid-only block never starts its dump timer.
- The tick driver `source_factory_tick_buildings_state(game, seconds)` (extended in place, still N2110) now calls `dumpOutputs()` every tick after the craft check — the Java order (GenericCrafter.java:259-264 calls `craft()` then `dumpOutputs()` via `updateTile()`).
- New owner constants `PORT_GAME_SOURCE_FACTORY_BUILD_DUMP_INTERVAL_STATE`, `PORT_GAME_SOURCE_FACTORY_BUILD_DUMP_TIMER_STATE`, `PORT_GAME_SOURCE_FACTORY_BUILD_DUMP_LIQUID_STATE`, `PORT_GAME_SOURCE_FACTORY_BUILD_DUMP_OUTPUTS_STATE` in `SourceRuntimeOwnerGameplayRegistry.gd`.
- Emitter change: `content_registry.py` now captures `liquidOutputDirections` per GenericCrafter-family block — the block initializer's own array (the electrolyzer's `{1, 3}`, Blocks.java:1395), else the class default `{-1}` (GenericCrafter.java:34). Registry: cryofluid-mixer `[-1]`, electrolyzer `[1, 3]`, silicon-smelter `[-1]`. The `content_registry_blocks` shard mirror was rebuilt (the N2114 lesson); all five `production_*` / registry shards on disk equal a fresh build.
