## Ownership and actual API boundary

`SourceBuildingItemState` gains `source_handle_stack_wake_state` (N2044) and `source_remove_stack_wake_state` (N2045). `SourceBuildingAccessState` gains `source_on_proximity_update_wake_state` (N2046).

- **N2044 handleStack wake.** `noSleep()` runs first, then the stack is added. Delegates to the existing `handle_stack_count` for the count and to `no_sleep_state` for the wake transition. Result keys: `count_before, count_after, sleep_time_before, sleep_time_after, sleeping_before, sleeping_after, sleeping_entities_before, sleeping_entities_after, woke, add_called`.
- **N2045 removeStack wake.** Delegates to the existing `remove_stack_state` for the clamped removal. Without an items module the Java null guard returns 0 before `noSleep`, so the result keeps sleepTime, sleeping and sleepingEntities untouched (`woke` false, `add_called` false). With an items module, `noSleep` runs, then the clamped stack is removed. Result keys: `removed, remaining, return_value` plus the eight wake keys.
- **N2046 onProximityUpdate wake.** The whole Java method is `noSleep()`, so this binding delegates to `no_sleep_state` and re-keys the result. It is the superclass wake, distinct from the power-domain `onProximityUpdate` state at N968, which covers the power graph side of the same call. Result keys: the eight wake keys.
