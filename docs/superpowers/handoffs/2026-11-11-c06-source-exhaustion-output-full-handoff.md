## What this batch is

The live-loop power stamp (`SourceFactoryRuntimeState.source_factory_update_power_graph_state`, N2077 driver, extended in place by N2125) stamps each grouped consumer dict's `should_consume` / `shouldConsumePower` from `SourcePlacedPowerGraphState.source_consumer_should_consume_for_cell_state(game, cell)`. N2125's version of that helper read only the placed building's live frame `enabled` flag. That left two Java acts unwired for the factory families:

- **Output-full:** `GenericCrafterBuild.shouldConsume()` (GenericCrafter.java:203-231) returns false when an output item's held stack plus one output would exceed itemCapacity, or when every output liquid is full at `liquidCapacity - 0.001f` and `dumpExtraLiquid` is true — and `ConsumePower.requestedPower` (ConsumePower.java:60-63) charges an unbuffered consumer `usage * (entity.shouldConsume() ? 1f : 0f)`, so an output-full factory must request nothing. The adjacent family's own body is the same `entity.shouldConsume()` factor for those builds (Separator.java:99-108 counts held items minus consume inputs against itemCapacity, WallCrafter.java:246-248, BlockProducer.java:108-110, else the Building default). The helper now calls the family's per-class shouldConsume for `should_consume`: `source_factory_should_consume_state` for a `source_factory_building` frame (with the sprite's liquid module and the catalog's liquid ids), `source_adjacent_factory_should_consume_state` for a `source_adjacent_factory_building` frame.
- **Source-exhaustion:** `BuildingComp.updateConsumption()`'s first pass (BuildingComp.java:1971-1974) clears `shouldConsumePower` when a non-power, non-optional consumer's efficiency is at most 0.0000001f, and `PowerGraph.getPowerNeeded` (PowerGraph.java:105-115) sums only consumers whose `shouldConsumePower` is set — so a starved factory stops drawing power even while its outputs have room. The tick already computes that flag (`SourceBuildingEfficiencyState.update_consumption_non_optional_pass_state`, stamped on the frame by `apply_update_consumption_state` from the factory tick driver, SourceFactoryBuildState.gd:953, and the adjacent driver, :344), so the helper now reads the frame's live `should_consume_power` key, falling back to `enabled` before the first tick. The other families keep the enabled-only read: their per-class shouldConsume bodies (UnitFactory plans, N2124) are not wired to the stamp yet.

One ordering fact the proof has to respect: in `simulate_factory`, `source_factory_update_power_graph_state` runs at line 163 — BEFORE `source_factory_tick_buildings_state` (line 186) — so the power stamp reads the frame's `should_consume_power` from the PREVIOUS tick's consumption pass: one tick stale, still live state. The proof drives five ticks per phase so the flag settles before each read.
