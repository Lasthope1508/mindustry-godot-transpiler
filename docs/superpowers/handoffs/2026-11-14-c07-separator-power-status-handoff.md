## Scope (decided at RED)

- Family: the Separator implementation family — two defs, **separator** (consumePower 1.1f, Blocks.java:1243; size 2, craftTime 35f, Blocks.java:1231-1246) and **disassembler** (consumePower 4f, Blocks.java:1262; size 3, craftTime 15f, itemCapacity 20, Blocks.java:1248-1266). Separator extends Block (Separator.java:19, `public class Separator extends Block{`); its build extends Building (Separator.java:75). Catalog confirms implementation Separator + consumePower 1.1 / 4.0 + hasPower true + consumesPower true + powerUsage 1.1 / 4.0 (source_modules/content_registry_blocks.json, separator / disassembler entries). Blocks.java defs are the source of truth, see Exact exprs.
- Why: the separator has NO driver at all — it extends Block, not a factory or crafter, so no existing driver matches it, and no frame key exists for it, so the N2142 stamp never reaches a separator frame. Its updateTile progress advance (Separator.java:133) gates on `efficiency > 0`, so a separator with no power would advance progress as if power.status were 1.0. N2169 is the separator's live read — the same proven N2145–N2168 pure-row pattern, on the N2166 payload-deconstructor precedent (new family file + own driver + own frame key + simulate_factory wiring): one new pure function on a new state file + a driver fold + a new frame key + the wiring. The same driver covers both defs via the catalog consumePower; the disassembler def waits for its own verification slice.
- SeparatorBuild HAS a shouldConsume override (Separator.java:92-100, `return total < itemCapacity && enabled;`, where total = items.total() minus the consItems input stacks), so the BuildingComp default (BuildingComp.java:755, `public boolean shouldConsume(){`) does NOT apply here — the gate is deferred (items state is not tracked yet) and the machinery runs with should_consume=true when enabled (the MendProjector suppression precedent).
- The separator also consumes liquid slag (separator 4f/60f, Blocks.java:1244; disassembler 0.12f, Blocks.java:1264) — power-only first pass, the liquid row waits for its own slice, so the folded efficiency is the min over the modeled consumers (power only).
- The updateTile advance (progress / warmup / totalProgress / consume() / offload random result item / dump, Separator.java:128-166) waits for its own slice — the proof carries no progress/warmup/offload keys; the efficiency > 0 gate (Separator.java:133) is what the efficiency keys prove.
- Out of scope for this slice: the updateTile advance / shouldConsume gate / liquid consumer row / disassembler variant verification / sense / canDump / draw / icons / read-write / created / shouldAmbientSound rows — all deferred, see register script DEFERRED (109 entries = 101 carried from N2168 + 8 new N2169 entries).
